# Project 1: Automated HIPAA-Compliant Multi-Cloud Kubernetes Platform

**Role:** Lead Infrastructure Engineer

**Objective:** Architected and deployed an automated, secure, production-grade container orchestration platform across AWS and Azure to host regulated healthcare workloads while maintaining strict HIPAA compliance.

### Key Responsibilities and Technical Achievements

- **Infrastructure as Code (IaC):** Utilized Terraform to provision highly available, private Kubernetes clusters using AWS EKS and Azure AKS, isolating cluster endpoints and worker nodes from direct public internet exposure.
- **Secure Networking and Access Control:** Implemented multi-region VPC peering and transit gateways. Configured Kubernetes RBAC integrated with Microsoft Entra ID (formerly Azure AD) and AWS IAM Roles for Service Accounts (IRSA) to enforce least-privilege access.
- **Security and Compliance Guardrails:** Integrated Trivy and Wiz into deployment pipelines to scan container images for vulnerabilities and infrastructure configurations for security misconfigurations before publishing images to Amazon ECR and Azure Container Registry (ACR).
- **GitOps and Continuous Delivery:** Deployed Argo CD to manage infrastructure add-ons and application workloads using declarative GitOps practices, reducing manual intervention in production environments.
- **Measurable Impact:** Reported a reduction in infrastructure configuration drift to 0% and an 84% improvement in audit-readiness documentation delivery time through automated compliance scanning.

### Technical Reference Documentation

1. [Terraform: Provision an AWS EKS Cluster](https://developer.hashicorp.com/terraform/tutorials/kubernetes/eks)
2. [Azure AKS Production Baseline Architecture](https://learn.microsoft.com/en-us/azure/architecture/reference-architectures/containers/aks/baseline-aks)
3. [Argo CD: Declarative Setup and GitOps Patterns](https://argo-cd.readthedocs.io/en/latest/operator-manual/declarative-setup/)

# Project 2: Data-Driven Infrastructure Observability and FinOps Optimization Platform

**Role:** DevOps & Platform Engineer

**Objective:** Designed a centralized, scalable observability framework across AWS and Google Cloud Platform (GCP) to translate system telemetry into actionable operational KPIs and infrastructure cost optimization opportunities.

### Key Responsibilities and Technical Achievements

- **Telemetry Collection:** Deployed OpenTelemetry Collectors as Kubernetes DaemonSets to collect distributed traces, logs, and system metrics from production clusters while minimizing vendor lock-in.
- **Metrics Storage and Visualization:** Managed monitoring infrastructure using Prometheus and Grafana, developing executive-level dashboards that connected technical metrics—including CPU utilization, memory consumption, and network I/O—to operational KPIs.
- **Cloud Operations and Event Management:** Integrated Datadog and Azure Monitor with a centralized incident-routing workflow through ServiceNow, improving alert quality and reducing unnecessary notifications.
- **FinOps and Cost Optimization:** Engineered automated data pipelines using cloud billing exports to identify underutilized resources and support data-driven cost optimization across multi-cloud environments.
- **Measurable Impact:** Reported savings of more than 500 hours of manual operational effort annually, a 25–30% reduction in system downtime, and more than $200,000 in infrastructure costs protected through data-driven resource optimization.

### Technical Reference Documentation

1. [OpenTelemetry: Kubernetes Deployment and Instrumentation](https://opentelemetry.io/docs/platforms/kubernetes/)
2. [Google Cloud: Export Billing Data to BigQuery](https://docs.cloud.google.com/billing/docs/how-to/export-data-bigquery)
3. [Grafana: Dashboard Design and Best Practices](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)

# Project 3: Automated Disaster Recovery and Business Continuity Framework

**Role:** Site Reliability / DevSecOps Engineer

**Objective:** Built and validated a production-grade, multi-region disaster recovery (DR) automation framework for mission-critical enterprise systems spanning AWS and Google Cloud Platform.

### Key Responsibilities and Technical Achievements

- **State and Volume Replication:** Configured cross-region backup and snapshot replication workflows for production databases and block storage volumes, incorporating managed encryption keys and recovery requirements.
- **Declarative Namespace Recovery:** Developed automation scripts and wrappers around cloud-native backup tooling to export, validate, and restore Kubernetes resources and stateful workload configurations.
- **CI/CD Pipeline Promotion:** Customized GitHub Actions and Azure DevOps multi-stage workflows to coordinate cluster promotion, DNS failover procedures, and environment-level rollback operations.
- **Automated Validation and Testing:** Established recurring disaster recovery exercises and simulated infrastructure failures to validate recovery procedures against defined data-loss and recovery-time objectives.
- **Measurable Impact:** Reported a 25–30% reduction in operational risk indicators while improving recovery readiness against internal Recovery Point Objective (RPO) and Recovery Time Objective (RTO) requirements.

### Technical Reference Documentation

1. [AWS Backup: Cross-Region and Cross-Account Backup Copies](https://docs.aws.amazon.com/aws-backup/latest/devguide/recov-point-create-a-copy.html)
2. [GitHub Actions: Deployment Environments and Approval Gates](https://docs.github.com/en/actions/concepts/workflows-and-actions/deployment-environments)
